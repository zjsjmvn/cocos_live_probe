# 通用 Cocos 实时探针：截图、输入、条件等待与持续诊断

状态：用户已授权发布及实现；测试边界采用现有公共命令入口和真实 Cocos 场景。

跟踪事项：[GitHub Issue #1](https://github.com/zjsjmvn/cocos_live_probe/issues/1)。

## Problem Statement

Cocos Live Probe 已经能读取运行中的场景树、节点、Transform、组件、渲染 bounds 和动画，并通过 CLI `eval/eval-file` 执行自定义诊断脚本。AI 可以检查游戏内部状态，但还不能通过统一工具直接查看画面、发送真实浏览器输入、等待通用状态条件，以及读取持续收集的错误记录。

开发者希望看着有窗口的 Chromium，与 AI 在同一个受管页面上检查问题。仅调用 Cocos 内部输入分发器无法验证浏览器到引擎的完整输入链路；仅返回脚本结果也会遗漏 console、异步异常和资源加载失败。页面刷新、窗口缩放或场景变化后继续使用旧截图和旧节点，还可能误操作。

本轮增强应保持探针通用，不认识米桶、阶段、金币等游戏业务概念，也不重做已有场景查询、会话隔离、命令队列和脚本执行能力。

## Solution

在现有 CLI 和 MCP 上新增四项能力，并补充指定 Chromium 可执行文件的配置：

| 能力 | MCP 工具 | CLI 命令 | 用户可见结果 |
| --- | --- | --- | --- |
| 截图 | `runtime_screenshot` | `screenshot` | 当前受管页面的图片、本地文件和对应的视口/缩放信息 |
| 输入 | `runtime_input` | `input` | 鼠标、触摸和键盘的真实输入结果，包含定位与发送状态 |
| 等待 | `runtime_wait` | `wait` | 节点出现/消失或属性条件满足的结果，包含耗时及超时原因 |
| 诊断 | `runtime_diagnostics` | `diagnostics` | 有界的 console、异常、Promise 拒绝和网络失败记录 |

用户可以完成“截图 → 发送输入 → 等待状态变化 → 读取现有节点/动画快照 → 再截图”的检查流程。购买、领取等业务是否成功，仍由调用者根据项目状态判断。

保留现有八个 MCP 工具以及 CLI `eval/eval-file`。Creator 编辑器 MCP 继续负责资产刷新；运行时探针只刷新自己拥有的页面并检查场景就绪。场景就绪不等于已加载新代码。

## User Stories

1. 作为 Cocos 开发者，我希望指定已安装的 Chromium 可执行文件，以便使用选定版本而不依赖默认 Chrome 安装。
2. 作为 Cocos 开发者，我希望配置错误的浏览器路径时收到明确错误，以便修正配置而不是无意间测试另一个浏览器。
3. 作为 Cocos 开发者，我希望看到受管页面的 Chromium 窗口，以便直接观察 AI 的操作并人工复核。
4. 作为 AI 调试助手，我希望获知实际连接的浏览器版本、CDP 地址和 target，以便确认测试环境。
5. 作为 AI 调试助手，我希望获取当前页面截图，以便将内部状态与实际画面对照。
6. 作为 MCP 客户端，我希望截图以图片内容块返回，以便直接进行视觉观察。
7. 作为 Cocos 开发者，我希望截图同时保存到本地，以便复查和分享诊断证据。
8. 作为 AI 调试助手，我希望获知图片尺寸、视口尺寸、Canvas 范围和缩放信息，以便正确换算点击坐标。
9. 作为 AI 调试助手，我希望截图和输入返回页面身份及刷新代次，以便确认操作依据属于当前页面。
10. 作为 AI 调试助手，我希望旧页面或旧视口的输入被拒绝，以便避免在刷新或缩放后误点。
11. 作为 AI 调试助手，我希望通过视口 CSS 像素发送鼠标点击，以便验证真实的浏览器输入链路。
12. 作为 AI 调试助手，我希望发送触摸点击，以便检查游戏的触摸输入适配。
13. 作为 AI 调试助手，我希望发送按键及组合键，以便检查键盘控制。
14. 作为 AI 调试助手，我希望执行有时长上限的长按，以便测试持续输入。
15. 作为 AI 调试助手，我希望按起点和终点执行拖动，以便检查拖拽交互。
16. 作为 AI 调试助手，我希望通过节点 UUID 定位输入位置，以便复用已有节点查询结果。
17. 作为 AI 调试助手，我希望节点输入自动处理相机投影、Canvas 缩放和坐标原点，以便在不同窗口尺寸下操作同一节点。
18. 作为 AI 调试助手，我希望失效、不可投影或存在歧义的节点定位返回明确原因，以便重新选择目标。
19. 作为 Cocos 开发者，我希望弹窗遮挡时输入仍经过浏览器和引擎的正常命中过程，以便发现交互遮挡问题。
20. 作为 AI 调试助手，我希望分别获知定位是否成功及输入是否已发送，以便不把输入已发送误认为业务操作成功。
21. 作为 Cocos 开发者，我希望输入结束或中途失败时释放按键、鼠标和触摸，以便不会留下卡住的输入状态。
22. 作为 Cocos 开发者，我希望输入失败时不会自动重放，以便避免重复购买或重复领取。
23. 作为 AI 调试助手，我希望等待节点出现，以便在异步加载完成后继续检查。
24. 作为 AI 调试助手，我希望等待节点消失，以便确认弹窗关闭或对象销毁。
25. 作为 AI 调试助手，我希望等待节点或组件属性满足条件，以便减少诊断脚本中的固定延时。
26. 作为 AI 调试助手，我希望等待请求有明确超时及最后一次观察结果，以便分辨条件未满足、节点失效和页面失联。
27. 作为 AI 调试助手，我希望场景切换后重新定位节点，以便不会读取已销毁对象。
28. 作为 AI 调试助手，我希望获取持续收集的 console 日志，以便检查执行过程和警告。
29. 作为 AI 调试助手，我希望获取运行时异常及未处理 Promise 拒绝，以便发现脚本返回结果之外的异步错误。
30. 作为 AI 调试助手，我希望获取网络加载失败及 HTTP 错误状态，以便区分资源问题和游戏逻辑问题。
31. 作为 AI 调试助手，我希望诊断记录包含时间、级别、页面身份和可用调用栈，以便将错误与操作对应。
32. 作为 Cocos 开发者，我希望知道采集开始时间、采集中断和记录截断情况，以便不会把未采集到误认为没有错误。
33. 作为 AI 调试助手，我希望按游标增量读取日志，以便连续调试时不反复接收同一批记录。
34. 作为 Cocos 开发者，我希望日志容量和对象序列化受到限制，以便长时间调试不会无限占用内存。
35. 作为并行调试的开发者，我希望每个 stdio MCP 会话只操作自己的页面并收集自己的日志，以便其他会话不受影响。
36. 作为 CLI 用户，我希望保留既有命令和脚本行为，以便宿主项目现有回归仍可运行。
37. 作为其他 Cocos 项目的开发者，我希望这些能力无需 CountRice 业务字段，以便直接使用同一通用探针。
38. 作为 AI 调试助手，我希望不支持的 Cocos 能力给出明确说明，以便不会把版本差异误认为业务失败。

## Implementation Decisions

以下是基于已讨论范围收敛的实现约束；新增参数的具体名称由实现统一确定，并写入 CLI 帮助与 MCP schema。

### 1. 复用现有模块与生命周期

- 扩展现有命令模型、RuntimeProbeService、CDP 客户端、Cocos 查询表达式及 CLI/MCP 适配层，不引入第二套驱动服务或替换 CDP。
- 新增命令走现有服务入口及串行队列，遵守 target ID、BrowserContext ID 和完整受管 URL 的所有权校验。
- stdio MCP 持续复用会话页面；结束时释放本会话上下文和监听，不关闭共享浏览器或其他会话。CLI 保持 `manual-cli` 的共享页面语义；HTTP MCP 保持单服务实例的共享语义。
- 保留按 workspace 隔离的 profile、启动锁、共享 target 锁、`autoReload=false` 和已有防节流开关。
- 截图、输入、等待和诊断均通过 CLI/MCP 使用；MCP 继续不暴露任意 `eval/eval-file`。

### 2. 浏览器配置与可见页面

- 新增 `COCOS_RUNTIME_PROBE_BROWSER_EXECUTABLE`，同时允许服务选项指定浏览器可执行文件。服务显式选项优先于环境配置，未配置时保留现有 Chrome 自动发现。
- 明确指定的路径无效时直接报错，不静默回退。路径通过进程参数传递，支持空格，不拼接为 shell 命令。
- 默认支持有窗口运行，受管页面可人工查看。复用外部已运行的 CDP 浏览器时，报告实际浏览器信息，明确可执行文件配置仅影响本工具发起的启动。
- 安装及版本固定采用文档说明，由用户安装所选 Chromium 发行版；本轮不自动下载、升级浏览器，也不硬编码本机缓存目录或 Chromium 版本。

### 3. 页面身份与观察凭据

- 新能力结果携带 `targetId`、`refreshGeneration`、会话身份和采集时间。截图额外返回可供后续输入引用的观察凭据，覆盖当前文档及视口/Canvas 几何信息。
- 输入必须携带当前页面身份；基于截图发起的坐标输入还须引用截图观察凭据。旧凭据被拒绝并提示重新观察，不自动转向替代 target。
- 除显式刷新外，人工 F5、顶层导航和 target 替换也必须使旧文档凭据失效。不同进程中的 CLI 不得仅因刷新计数重新从零开始就接受旧凭据。
- 窗口缩放、浏览器缩放或 Canvas 几何变化后，拒绝依赖旧截图的坐标输入。该校验只保证页面与几何关系，不保证画面中的动态对象仍在原位置。
- Cocos 场景切换不必导致浏览器文档刷新；节点操作每次重新解析 UUID，并验证节点存活、活动状态及当前投影，不能缓存已销毁的节点对象。
- 保留已有 `status` 的缓存语义，新结果明确哪些信息来自实时检查，不将缓存 ready 状态当作当前页面仍然存活的证据。

### 4. 截图与坐标契约

- 第一版截图为当前页面视口的 PNG，不包含浏览器窗口边框，不加入整页拼接或录屏。
- MCP 返回原生 `image` 内容块及结构化元数据的文本块；CLI 返回元数据及图片绝对路径，避免把图片 base64 当作主要文本结果。
- 截图保存到项目隔离的诊断产物目录，返回绝对路径。采用有界保留策略，允许指定输出位置；文档说明默认保存位置、容量及清理方式。
- 元数据包括图片像素宽高、视口 CSS 宽高、devicePixelRatio、visual viewport 缩放/偏移及游戏 Canvas 的 CSS 边界。Canvas 无法唯一识别时允许截图，但节点投影须明确失败原因。
- 对外输入坐标统一为页面视口 CSS 像素，左上角为原点。实现负责换算截图像素与 CSS 坐标，不把 devicePixelRatio 等同于全部缩放关系。

### 5. 真实浏览器输入

- 支持鼠标点击、触摸点击、键盘按键/组合键、鼠标或触摸长按与拖动。输入类型显式指定，不用一次操作同时模拟鼠标和触摸而重复触发事件。
- 点击及长按支持 CSS 坐标或节点 UUID；拖动的起止目标遵守同一坐标契约。键盘输入发往当前受管页面，并报告焦点相关失败。
- 所有输入通过 CDP Input 发送。节点定位只提供坐标，不调用 Cocos 内部事件分发器，不绕过弹窗遮挡或游戏输入锁。
- 首轮保证 Cocos 3.8 的 Canvas/UITransform 节点定位，处理节点变换、相机、Canvas 适配及 CSS 缩放。多相机或多 Canvas 无法唯一选择时要求明确定位上下文；任意 3D 对象的可点击位置推断不作为首轮承诺。
- 不存在、inactive、失效、不可投影或视口外的节点，以及无效坐标、时长和拖动参数，在发送前返回明确错误。
- 每次输入均有总时限。成功、超时、错误和正常服务清理时释放本次持有的键、鼠标按钮及触摸。连接已失去时报告清理未确认，不能声称成功释放。
- 发生部分输入后不自动重试，返回输入是否开始、是否完整发送和清理结果。业务成功由后续查询或等待判断。

### 6. 条件等待

- 支持节点存在、节点不存在和节点/组件属性条件。节点存在与 `activeInHierarchy=true` 分开表达；节点 inactive 不等于不存在。
- 存在性条件复用既有 selector 查询；属性条件要求唯一节点及明确组件/属性路径，支持 JSON 基本值的相等、不等与数值比较。不接受任意 JavaScript 谓词。
- 属性路径只用于读取，禁止方法调用和修改；无法读取、歧义和不支持的属性返回明确原因。组件私有字段不提供跨 Cocos 版本保证。
- 采用有界轮询及单调时间超时。建议默认超时 5 秒、上限 30 秒、默认间隔 100 毫秒，并与 MCP 工具超时保持一致；最终常量在帮助和 schema 中统一记录。
- 成功返回满足的条件、实际值及耗时。超时返回最后观察值；页面丢失、文档代次变化和能力不支持分别报告，不能统一伪装为条件超时。
- 等待在当前会话命令队列中执行，可观察游戏自身的异步变化；调用者应先完成输入再等待，不能依赖排在等待后面的同会话命令满足条件。
- 本轮不增加引擎帧等待、帧率采样或通用状态差异比较。

### 7. 持续诊断

- 在连接受管 target 时建立持续 CDP 事件订阅，收集 console 调用、运行时异常、未处理 Promise 拒绝及 Network 加载失败；HTTP 4xx/5xx 单独记录响应状态，不与传输失败混淆。
- 对工具新建的页面尽量在导航前启动采集。连接已运行页面时，只承诺订阅启用之后的记录；返回实际采集起点，不声称可以恢复历史日志。
- 每条记录包含递增游标、时间、类型/级别、target、文档代次及可用的消息、URL、调用栈。协议未提供的字段明确缺失，不补造调用栈。
- 异常和 Promise 拒绝可通过同一异常事件产生，避免将同一事件重复记录。存在多来源去重时保留足以审查的原始类型信息。
- 持续采集独立于正在执行的服务命令，长按、等待、采样和 CLI eval 执行过程中仍可接收事件。
- 使用同时限制条目数、总字节数和单条内容大小的环形缓冲区。默认建议 1000 条、总计 2 MiB、单条 16 KiB；溢出时淘汰最旧记录并报告丢弃/截断情况。序列化限制深度并处理循环引用，不无限展开对象或保留远程对象句柄。
- 诊断读取支持类型/级别过滤、游标和最大返回条数。读取不隐式清空；游标已被淘汰时明确报告缺口。断连或恢复时标记采集空档。
- 页面刷新后重建所需订阅，旧记录保留其原始文档标记，不与新文档混为一批。其他 target 的日志不得进入本会话缓冲区。
- 长期 stdio/HTTP MCP 服务在连接存续期间采集历史。每次 CLI 调用仅能获得自身连接期间的记录，不承诺跨进程持续历史；CLI eval/eval-file 可通过显式选项一并输出本次执行期间的诊断记录，默认输出保持兼容。
- 无活动 Cocos 场景时仍可返回已经取得的页面错误，避免场景就绪失败使诊断入口也不可用。

### 8. 能力边界与刷新

- 报告可检测的 Cocos 版本及本轮能力的支持状态；缺失或版本未知时如实报告。基于私有字段的能力独立检测，不推断所有功能都支持。
- 通用服务不添加任何 CountRice 业务状态或断言。项目专用逻辑继续通过外部 CLI eval-file 脚本读取和验证。
- Creator MCP 负责资产刷新，宿主项目负责确认编译产物或版本证据；运行时探针执行会话页面刷新及场景就绪检查。无版本证据时，新代码是否生效为未确认。
- Chromium 不保证解决所有 target lost、ready timeout 或渲染问题。本轮不采集 GPU renderer、帧间隔或性能 trace。

## Testing Decisions

### 主要测试边界

以现有 `RuntimeProbeService.dispatch` 公共命令入口为主要行为测试边界，复用已有可注入的浏览器/CDP、时间及文件依赖。验证命令结果、可观察事件和错误，不对内部辅助函数组织、生成脚本字符串或固定 CDP 调用顺序建立脆弱断言。

CLI 和 MCP 只补公共协议契约测试，确认参数校验、命令映射、错误输出及 MCP 图片内容块。复用现有 FakeRuntimeProbeEnvironment、FakeSocket、CLI 生命周期、MCP 消息和 HTTP 测试的模式；为持续事件扩展已有传输依赖，不在每个内部模块创建新的独立测试边界。

另用一份无游戏业务依赖的真实 Cocos 3.8 测试场景，串行验收浏览器输入、截图和坐标转换。fake CDP 测试不能证明浏览器到 Cocos 的实际输入链路正确。

### 必须覆盖的外部行为

1. 浏览器显式配置优先级、路径含空格、无效路径报错、无配置时原有默认行为以及复用外部 CDP 时实际版本报告。
2. 同一 target 的截图可解码、保存路径真实可读、元数据匹配图像和视口，MCP 返回 image 内容块；文件保存失败如实报告。
3. 真实 UI 按钮在鼠标及触摸点击后改变通用测试计数；截图、现有节点查询和条件等待反映同一页面的变化。
4. 修改窗口尺寸、浏览器缩放及 Canvas 适配后，重新观察能正确输入；基于旧几何的坐标输入被拒绝。
5. UUID 输入正确处理节点变换和相机投影；弹窗阻挡底层按钮时，底层计数不变，不把输入已发送当作按钮已执行。
6. 键盘组合键、长按和拖动可被测试组件观察；中途协议失败或超时后的后续输入不保持残余按压状态，且不重放已发送输入。
7. 显式刷新、人工 F5、顶层导航、target 恢复和 CLI 新进程均不能使旧观察凭据重新有效；没有输入发往其他会话或仅同源的页面。
8. 场景切换后旧 UUID 输入明确失败，重新查询得到的新节点可操作；不存在、inactive、歧义及不支持的定位返回可区分错误。
9. 等待节点出现/消失、属性相等及数值比较成功；inactive 与不存在不同；超时、非法参数、属性缺失和页面丢失分别报告。
10. 等待超时后队列可继续执行；另一会话不受阻塞；同会话刷新与输入遵守串行关系。
11. console 各级日志、同步异常、未处理 Promise 拒绝、HTTP 错误和传输失败均进入对应 target 的诊断结果，并包含实际可获得的时间与调用栈。
12. 等待及 eval 执行期间继续采集事件；刷新后采集恢复；服务释放后停止监听并释放资源，不关闭其他会话页面。
13. 循环对象、大消息和大量日志不突破容量限制；增量游标、淘汰缺口、截断及断线采集空档有可见标记。
14. 没有就绪场景时仍可诊断页面加载异常；一次性 CLI 不冒充长期日志采集，默认 eval 输出兼容。
15. 原有八个 MCP 工具、CLI eval/eval-file、普通与骨骼动画读取、shared/isolated 所有权以及已有生命周期测试继续通过。

实现验收运行 `npm run typecheck`、`npm test` 和上述真实 Cocos 场景流程。真实场景验收缺少浏览器或 Creator 预览服务时明确记录未完成，不用 fake 测试结果代替。

## Out of Scope

- 新增 MCP eval/eval-file 入口，以及重复现有查询能力的大型 runtime_observe 工具。
- 引擎帧等待、帧率/帧间隔、GPU renderer、性能 trace、heap snapshot、断点及源码映射调试。
- 通用状态采样/差异比较、输入录制回放、视频、自动失败现场打包。
- CountRice 的米量、阶段、金币、输入锁等专用模型或业务成功断言。
- 任意 3D 对象的可点击位置推断、多指手势及完整移动设备仿真。
- 自动安装或升级 Chromium，引入 Playwright MCP 或 chrome-devtools-mcp，替换当前 CDP 驱动。
- 实现 Creator 编辑器资产刷新、资源版本快照或仅凭场景 ready 证明新代码已生效。
- 跨 CLI 进程常驻日志服务、HTTP MCP 按客户端隔离、取消现有对话级隔离。
- 重做已完成的子模块接入，迁移宿主游戏脚本目录或删除旧兼容入口；目录命名清理另开事项。
