# 通用探针取证增强：统一验收包、输入命中反馈与渲染确认

状态：规格阶段，按本次 to-spec 请求发布为 ready-for-agent；本规格不代表功能已实现。

跟踪事项：[GitHub Issue #3](https://github.com/zjsjmvn/cocos_live_probe/issues/3)。

## Problem Statement

开发者已经能够用 Cocos Live Probe 查询场景、截图、发送真实输入、读取诊断，并使用项目游戏扩展执行单步或有界自动玩。当前工作区也已有桌面 Inspector 和让 AI 接入人工游戏现场的能力。

现在一次调试的证据仍然分散：截图保存为单独的产物，日志依赖当前服务的诊断缓冲，游戏报告由调用方自行保存。调用结束后，开发者很难快速确认某张图属于哪次输入、哪份文档、哪个游戏状态和哪次代码修改。连接中断或缓冲淘汰后，还可能误把不完整证据当成完整记录。

输入回执目前能够说明定位、发送与释放是否完成，却不能说明游戏中的哪个 UI 节点实际收到事件。因此遇到“点不动”时，AI 需要额外猜测坐标换算、遮挡、事件路径与业务输入锁。命中节点也不能证明升级、领奖或阶段切换已经成功，这些证据需要分开表达。

当前引擎就绪主要依据 Cocos 和活动场景存在。场景存在不意味着对应画面已经渲染。依赖固定延迟容易得到空白截图，或者把上一场景画面与新场景状态配在一起；接入暂停的 bug 现场时，又不能为了等待画面偷偷恢复、重载或更换页面。

## Solution

首版增加三项通用能力，借鉴 AI-Eyes 的公开设计，复用现有探针的页面身份、队列、真实输入和诊断：

1. **统一验收包**：把一次明确的调试运行中已有的命令、截图、诊断、输入回执和可用游戏报告归档，返回可直接打开的清单与证据目录。证据缺失、采集间隙、淘汰和截断都明确记录。
2. **输入命中反馈**：在真实指针输入期间观察 Cocos 实际事件分发，返回命中节点身份、事件阶段和坐标证据。区分已命中、明确未命中、未知、不支持和不适用；继续独立验证业务效果。
3. **渲染确认**：提供显式的当前场景渲染等待入口，并允许截图要求先确认渲染。等待真实渲染事件，使用既有时间预算，不依赖固定 sleep，不改变游戏暂停或页面运行状态。

这三项同时服务 Chrome 预览、桌面 Inspector 和项目游戏扩展。指定帧截图、自述帮助接口、自动资源刷新与编译流水线留给后续规格。

## User Stories

1. 作为游戏开发者，我希望一次调试的证据有唯一运行标记，以便准确区分多轮验证。
2. 作为游戏开发者，我希望截图、日志和游戏报告保存在同一份验收包中，以便一次打开全部现场资料。
3. 作为游戏开发者，我希望证据记录页面、文档和刷新身份，以便发现运行过程中现场已变化。
4. 作为游戏开发者，我希望记录来源代码版本及工作区是否有修改，以便说明验证时的源码背景。
5. 作为游戏开发者，我希望来源代码版本与实际运行版本分别记录，以便避免把 Git 提交当成已加载脚本的证明。
6. 作为游戏开发者，我希望明确开始和结束一轮取证，以便按一次问题复现组织资料。
7. 作为 CLI 用户，我希望单次命令能自动生成验收包，以便无需维持额外的服务进程。
8. 作为 MCP 用户，我希望在已有会话中连续记录多条命令，以便保留一个完整的调试过程。
9. 作为桌面 Inspector 用户，我希望 AI 在同一个人工窗口取证，以便保留已经复现的 bug 状态。
10. 作为桌面 Inspector 用户，我希望导出证据不重载、不恢复游戏，以便暂停现场保持原状。
11. 作为多人或多会话工具用户，我希望不同服务和窗口的证据不会串在一起，以便信任证据归属。
12. 作为同一个共享 Inspector 的使用者，我希望知道当前正在记录哪一轮，以便避免无意开始重叠的运行。
13. 作为游戏开发者，我希望说明日志从什么时候开始采集，以便知道连接之前的异常可能未被记录。
14. 作为游戏开发者，我希望日志缓冲淘汰、连接间隙与截断可见，以便不会误以为“没有记录”等于“没有问题”。
15. 作为游戏开发者，我希望截图一旦收入验收包就能随包保留，以便临时截图清理不会使清单失效。
16. 作为游戏开发者，我希望截图失败或页面关闭时仍能导出已取得的证据，以便保留失败现场。
17. 作为游戏开发者，我希望取证有容量与保留数量限制，以便持续调试不会无限占用磁盘。
18. 作为游戏开发者，我希望写盘失败明确显示而不重放输入，以便不会因归档问题重复购买或领奖。
19. 作为自动玩调用者，我希望取证使用现有步骤前后状态和验证结果，以便避免重复读取引起额外耗时。
20. 作为自动玩调用者，我希望验收包保留已经发生的输入和最终停止原因，以便理解失败前游戏实际变化。
21. 作为游戏开发者，我希望给证据运行起一个可读名称，以便快速找到某次问题复现。
22. 作为游戏开发者，我希望能够导出已经结束的运行，以便程序退出后仍能查看证据。
23. 作为游戏开发者，我希望默认不开启新的持续落盘，以便既有调用保持原有成本和使用习惯。
24. 作为游戏开发者，我希望点击回执说明哪个 UI 节点实际收到事件，以便定位点击无效的原因。
25. 作为游戏开发者，我希望命中节点同时提供 UUID 与当时的路径，以便区分同名节点及之后的层级变化。
26. 作为游戏开发者，我希望看到实际使用的设备与事件阶段，以便知道验证走了鼠标还是触摸链路。
27. 作为游戏开发者，我希望看到截图像素、视口与 canvas 坐标之间的换算证据，以便定位缩放和位置偏差。
28. 作为游戏开发者，我希望有遮挡时反馈实际接住事件的上层节点，以便避免把期望目标当成真实命中。
29. 作为游戏开发者，我希望未知的命中结果不会被报告为未命中，以便不会因检测失败得到错误结论。
30. 作为游戏开发者，我希望没有 UI 节点接住但全局输入仍有效时继续查看业务结果，以便自定义玩法输入得到正确评价。
31. 作为自动玩调用者，我希望输入发送、节点命中与业务验证分别返回，以便不会把收到事件当作目标完成。
32. 作为游戏开发者，我希望拖动、长按和取消的反馈有界且不重复统计冒泡节点，以便能理解复杂交互。
33. 作为游戏开发者，我希望键盘输入明确标注 UI 指针命中不适用，以便避免出现误导的未命中结果。
34. 作为游戏开发者，我希望可选观察不会改变节点的事件资格或传播行为，以便调试结果与正常游戏一致。
35. 作为游戏开发者，我希望页面刷新、输入失败和服务关闭时解除观察，以便后续输入不受遗留监听影响。
36. 作为游戏开发者，我希望不兼容的引擎仍能使用既有真实输入，以便新增诊断能力不破坏原有工具。
37. 作为游戏开发者，我希望把场景存在和画面已渲染分开查询，以便准确判断能否截图。
38. 作为游戏开发者，我希望等待当前场景的真实渲染通知，以便不再猜固定等待时间。
39. 作为游戏开发者，我希望截图可以要求先确认渲染，以便减少启动和切场景时的空白或旧画面。
40. 作为游戏开发者，我希望渲染等待超时明确返回原因，以便发现引擎暂停、页面关闭或能力不支持。
41. 作为桌面 Inspector 用户，我希望等待渲染不会自动恢复暂停，以便 bug 现场不被工具推进。
42. 作为桌面 Inspector 用户，我希望已经确认过的当前场景画面在暂停后仍可识别，以便继续检查暂停现场。
43. 作为游戏开发者，我希望刷新或切场景后旧渲染确认失效，以便不会复用错误的画面凭据。
44. 作为游戏开发者，我希望渲染信息说明观察起点，以便不会把连接后第一次看到的帧当成游戏启动第一帧。
45. 作为游戏开发者，我希望等待、采集和归档遵守现有时间预算，以便工具调用不会无期限挂起。
46. 作为游戏开发者，我希望能力在 CLI、stdio MCP、HTTP MCP 和 Inspector 接入中保持一致，以便能切换调用方式。
47. 作为游戏开发者，我希望报告大小和步骤数量继续受限，以便 AI 调用不会被无限证据淹没。
48. 作为游戏开发者，我希望新增能力有真实 Cocos 和桌面运行验收，以便模拟输入成功不会代替实际引擎验证。
49. 作为 CountRice 开发者，我希望取证只读取快照并观察正常输入，以便 ECS 继续作为玩法状态权威。
50. 作为 CountRice 开发者，我希望能从验收包确认引导、升级和阶段继续的实际结果，以便回归检查保留可复核证据。

## Implementation Decisions

### 1. 范围与接入

- 能力属于通用探针，不复制 AI-Eyes 源码，不要求购买或安装该插件，不将新接口注册到 Creator 的预览 HTTP 服务。
- 服务调度、互动、诊断、游戏扩展、证据存储和现有 Inspector 适配负责各自行为；外部仍以公共 dispatch 为主要入口。内部复用当前命令执行路径，不递归调用公共 dispatch 造成队列死锁。
- 当前工作区的桌面 Inspector、AI 接入与原生 WebContents 调试适配是已有接入条件。实现时核实其最终接口并保留现有变更，不重复建设桌面程序，也不把尚未提交的工作区能力宣称为已发布功能。
- Chrome 与 Electron 复用相同的页面观察、输入反馈和证据契约；传输差异留在现有适配边界。不为诊断另开预览、替换 target 或悄悄回退到另一个浏览器。
- 现有截图、输入、游戏命令、诊断和 Inspector 接入语义保持兼容；新增字段为附加证据。原来的引擎 ready 含义保持原样，用独立字段表达渲染确认。

### 2. 证据运行与入口

- “服务会话”沿用现有 RuntimeProbeService 的连接与页面所有权。“证据运行”表示用户选择开始的一轮取证，以随机唯一 runId 标记，可覆盖该服务的多条串行命令；它与游戏存档或业务目标不是同一概念。
- 新增统一 evidence 控制入口，MCP 名为 runtime_evidence，CLI 名为 evidence，动作包括 start、finish、export。start 接受可读 label；finish 和 export 使用准确 runId，避免误结束或误导出别的运行。参数校验不接受任意执行代码。
- 长期服务和桌面 Inspector 受管服务可显式开始、结束运行。单个底层服务同时最多一轮活动取证，再次 start 明确报告已有运行，不隐式结束或混合它。共享 HTTP 或同一 Inspector 的调用者共享这一事实，需在说明与回执中显示。
- 普通 CLI 每次调用都销毁服务，不能靠多个独立进程的 start/finish 拼接内存中的运行。提供服务选项 evidence 以及环境选项 COCOS_RUNTIME_PROBE_EVIDENCE，用于显式开启单次主要命令自动归档；一次输入或 game-autoplay 调用即一轮。连接长期桌面服务的 CLI 可以使用该服务的活动运行。
- 自动归档默认关闭。显式 start 的运行覆盖该服务之后的已执行命令；开启按命令归档且已有显式运行时，命令加入已有运行，不建立重复的嵌套运行。证据控制、导出和内部子步骤不再次触发自动运行。
- 环境开关使用 on/off，缺省 off，非法值启动时明确失败。显式服务配置优先于环境变量；相对证据根目录按服务 workspaceRoot 解析，不能按碰巧的进程目录切换。label 最多 64 字符。
- 证据根目录由受信任服务配置或 COCOS_RUNTIME_PROBE_EVIDENCE_ROOT 指定，缺省为宿主工作区内可忽略的专用目录。MCP 不接受任意目录写入参数。label 只用于说明和经过处理的名称，不作为路径；runId 不能含路径分隔或目录跳转。
- export 读取已落盘运行并返回清单与绝对产物路径，不启动、刷新或接管旧页面。允许导出活动运行的当前快照，标注 in-progress；finish 生成终态。不存在、已清理或损坏的运行返回明确错误。
- finish 不取消另一条正在队列中执行的自动玩，也不插队；调用者按现有有界执行语义等待当前命令结束。输入释放仍由互动层负责。

### 3. 验收包内容与归属

- 清单至少包括 schemaVersion、runId、label、服务与页面身份、开始/结束时间、终态、源码背景、实际引擎版本、可用游戏扩展身份、采集范围、容量使用、截断与缺失说明，以及各项产物引用。
- runState 区分 in-progress、finished、incomplete，evidenceStatus 区分 complete、partial；业务目标是否达成及输入失败原因由命令结果独立表达。finished 表示运行正常结束，不表示游戏目标已完成；异常退出遗留的运行标为 incomplete。
- 每条已执行命令关联 runId 与递增 commandId，保存类型、经过限制的参数摘要、开始/结束时间、结果摘要、错误或停止原因。游戏子步骤关联父 commandId 和 step 序号，不伪装成额外的外部调用。
- 所有现场证据尽可能关联 instanceId、targetId、documentId、refreshGeneration、场景身份与观察时间。目标或文档更换必须成为可见的边界事件，禁止把两份文档的状态配成一次正常前后验证。
- 源码背景只记录可取得的提交标记、工作区是否有修改及来源；它不证明预览已经加载该提交。实际运行版本来自探针和可用的游戏桥，无法取得时标记 unknown。不采集完整环境变量、认证令牌或整份工作区文件。
- 截图保留取得时的身份、尺寸与几何凭据；收入包内时持有独立产物，防止临时截图淘汰导致引用丢失。包内引用采用可移动的相对关系，对外回执提供绝对清单和目录路径。
- 复用当前诊断记录及游标，保存采集开始、范围、间隙和淘汰信息；不能恢复服务连接之前的日志，不能因为归档开启就承诺无限历史。连接中途开启取证时只使用明确可取得的范围。
- 游戏报告复用已有 before、after、decision、input、verification、steps 和停止原因。只读状态继续遵守单份 64 KiB 上限，游戏工具回执继续遵守 256 KiB 上限及最近 50 条步骤上限。
- 已有截图和游戏状态优先复用。start 或 finish 可在剩余预算允许时补充当前只读状态与截图；页面丢失、暂停无法确认渲染或预算不足时记录缺失原因，不能为补证据重放输入、重载或恢复游戏。
- 首版完整记录探针命令发起的输入，不承诺记录所有人工原生输入、浏览器定时器和外部平台动作。清单说明输入覆盖范围；已知的人工面板编辑可标注来源，但不因此宣称存在可重放的全部输入序列。
- 成功的业务结果和完整的证据包是独立状态。写盘、截图或取证失败可以令证据 partial，并附有原因，不能改写已经发生的业务事实或触发重复输入。显式 evidence 控制失败通过现有结构化错误渠道返回。

### 4. 容量、持久化与生命周期

- 首版建议默认每运行最多 32 MiB、1000 条命令摘要、1000 条诊断记录，最多保留 20 轮，总证据目录最多 256 MiB。限制作为服务配置有明确合法范围，禁止以无穷值关闭约束。达到限额保留停止原因、汇总与缺失标记，省略大载荷或后续截图。
- 清单与命令回执各自最多 256 KiB，外置产物列表也必须有界。容量按实际写出/传输的字节计算，不以紧凑 JSON 的长度推断漂亮打印后的大小。清单写入需防止半份成功文件被当成 complete。
- 自动保留策略只清理同一受管根目录中可验证为探针创建、已经结束的运行，不删除活动运行、人工文件或显式外部产物。清理后的导出请求明确报告 unavailable，不返回失效的成功路径。
- 默认目录需加入版本控制忽略规则；源码和规格正常提交，证据产物不默认进入 Git。目录不可写、容量不足、文件损坏和文件名碰撞都须有可见结果。
- 启用取证后的新增观察与归档计入当前命令预算；可选补充证据不足时直接跳过并标注。显式控制命令使用有界超时，建议默认 5 秒、上限 10 秒；排队也计时。现有输入释放的最多 3 秒清理窗口保持不变。
- 服务正常关闭时结束自身活动运行，记录 service-closed。异常终止可能留下 in-progress 运行，后续导出按 incomplete 展示，不伪造正常结束。不得开启调用后继续运行的自动截图、游戏操作或无限写盘队列。

### 5. 输入命中契约

- 原有输入 status、started、completed、cleanupConfirmed 和 failureReason 保持各自含义；新增 deliveryEvidence 表达实际事件观察，业务效果仍由游戏 verify 或调用者的条件检查判定。
- deliveryEvidence 至少有采集状态、完整性、实际设备、实际派发阶段、命中结果、节点摘要、坐标证据和不可用原因。命中结果区分 hit、miss、unknown、unsupported、not-applicable；不把检测不可用或部分采集当成 miss。
- hit 只代表观察到本次指针事件实际分发到 UI 目标。节点记录事件目标的 UUID 和当时路径，冒泡观察者另有角色，不把所有 currentTarget 都冒充独立命中。派生触摸与鼠标事件需去重并保留实际路径说明。
- miss 仅在观测正常、动作采集完整且没有 UI 目标接住时成立。输入部分失败、观察安装失败、记录溢出或无法可靠关联本次动作时返回 unknown，并保留已经观察到的有限事实。键盘为 not-applicable。
- 读取反馈前确认该次输入经过可观察的事件处理边界，不能只以传输接口返回推断 UI 事件已经处理完毕。无法在剩余预算内证明观察窗口完整结束时返回 unknown/partial，不能把迟到事件报告为 miss。
- 若只记录到原始 DOM 或全局输入，不能宣称命中某个 Cocos UI 节点。未命中 UI 不自动令输入失败，也不自动阻止游戏 verify；直接监听全局输入或自定义绘制的玩法可能正常推进。
- 记录关联唯一 actionId 与当前文档，按实际事件类型、指针身份和观察窗口筛选；不能把背景、人工或另一服务的输入归入本次操作。不能可靠排除混入时明确标为 unknown/partial。
- 节点最多 32 项、事件摘要最多 128 项，超出显式 truncated；不返回 Cocos 对象引用、全部监听器或整个场景快照。可用帧号必须注明计数来源和起点，没有可靠帧号时省略并说明，不能编造启动帧。
- 坐标证据记录实际客户端坐标、视口、devicePixelRatio、相关 canvas 显示/渲染尺寸与已有 geometryKey；能唯一确定 canvas 时记录 canvas 身份和投影结果，无法唯一定位时标注未知。继续复用现有 UUID 定位与截图凭据校验。
- 真实输入仍通过现有浏览器或原生 WebContents 输入通道。不直接调用按钮回调、emit 玩法事件或私有引擎输入方法来产生“成功命中”。传输不支持所请求设备时明确失败，不能静默换设备后宣称触摸验收成功。

### 6. 观察的非侵入性

- 输入观察仅在该次动作的有限窗口内启用，在开始派发前就绪，覆盖正常释放或取消，并在返回前解除。初始化、读取反馈、清理均遵守剩余预算；失败不重放输入。
- 可在引擎公开事件分发边界观察实际结果，必须保持原有 this、参数、返回值、异常与传播顺序。禁止添加会使原本不接收触摸的节点获得触摸资格的监听，禁止改变命中测试和传播行为。
- 多次输入不累积包装或监听。结束、超时、刷新、场景变化和服务关闭都解除自己安装的观察；第三方已经改变边界时不覆盖它的更新。无法安全安装或清理时报告未知/不支持及采集原因。
- Cocos 3.8.8 为首个真实验收版本。既有跨版本读取与输入保持可用，无法提供命中观察的版本明确返回 unsupported，不仅凭版本号假定私有结构相同。

### 7. 当前场景渲染确认

- 新增 CLI render-ready 与 MCP runtime_render_ready，接受有界 timeoutMs，建议默认 5 秒、上限 10 秒。结果区分 rendered、timeout、paused-unverified、unsupported、page-changed，并返回 engineReady、场景身份、页面凭据、观察开始/完成时间及可靠时才有的帧信息。
- 在引擎存在且当前场景可读后等待真实的完成绘制通知或等价可验证信号，不以 requestAnimationFrame、DOM load、窗口 paint 或固定 sleep 单独证明当前 Cocos 场景已画出。若采用平台绘制信号，必须另证其对应的场景和文档，否则能力只能报告 unsupported/unverified。
- 渲染确认绑定 documentId、refreshGeneration 与当前场景身份。确认时再次验证身份；刷新、顶层导航、target 丢失和同文档场景替换使旧确认失效。不能用仅相同的场景名称复用凭据。
- 晚接入只能证明观察开始后看到当前场景完成渲染，不能声称已经捕获游戏启动的第一帧，也不能宣称相同帧号意味着确定性运行。
- 接入暂停现场时不自动 resume、tick、重载或换页面。已有匹配当前文档和场景的有效渲染证据可以返回；没有证据且因暂停不能等待新绘制时返回 paused-unverified。
- 截图入口增加显式 waitForRender 和 timeoutMs。未请求等待时保留原有截屏行为，并可附带当前已知的渲染状态；请求等待时只在确认 rendered 后截屏，否则返回相应结构化失败且不保存一张假称已就绪的画面。
- 渲染等待与截图共享一个从入队开始计算的总预算，不为两个阶段各分配完整超时。返回前检查截图身份仍与确认一致。证据验收示例优先使用严格等待截图；暂停现场允许使用普通截图，明确标注渲染状态未确认。
- 渲染观察在超时、页面变化或服务关闭后解除，无迟到截图和后台续等。launch/refresh 的既有引擎 ready 字段不改为渲染成功的代称，也不把打开 Inspector 变成重载操作。

### 8. 协议、界面与文档

- CLI、stdio MCP 和 HTTP MCP 的新工具发现、参数 schema、错误及实际输出容量保持一致。桌面 AI 接入将命令路由到同一底层服务和队列，清单必须使用实际桌面 target 身份，不能用客户端未连接的 Chrome 身份代替。
- 长期服务不因导出关闭人工窗口；AI 断开不关闭已有桌面取证，桌面服务退出才结束其活动运行。普通 CLI 自动归档、共享 HTTP 运行和长期桌面运行的生命周期在说明中分别列明。
- 在已有 Inspector 提供“保存验收包”入口，显示运行、完成/部分状态和产物路径。界面只提供与取证有关的操作，不要求用户理解传输或事件钩子的实现；不得为了导出刷新游戏。
- 更新使用说明，包含启用配置、三个证据动作、渲染等待、命中各状态、容量、暂停现场、日志覆盖范围，以及“发送成功、命中、业务成功”之间的关系。
- CountRice 示例复用现有项目插件和只读桥，用正常触摸完成引导、实际商店升级或阶段继续，再检查包中业务验证。遵守运行时/表现层边界、ECS 权威和独立米容器 ADR，不在通用探针复制金币、鸡槽或米容器规则。

## Testing Decisions

### 测试入口

沿用此前已确认的公共 RuntimeProbeService.dispatch 行为入口、CLI/MCP 协议入口和真实 Cocos 预览验收，不新增按内部辅助函数拆分的测试边界。新的 evidence 与 render-ready 命令也从同一 dispatch 入口验证。

好的测试只断言调用方可观察的身份、结果、文件内容、容量、输入次数、业务变化和运行现场是否保留，不断言私有方法、表达式字符串、钩子数量或固定 CDP 调用顺序。计时使用既有依赖或带合理余量的有界测试，不以精确毫秒或不必要的长 sleep 验证实现。

先例包括已有通用互动行为夹具、游戏扩展夹具、CLI 输出测试、stdio/HTTP 工具发现测试，以及真实引擎场景和桌面 Inspector 接入验收。扩展这些边界验证证据模块、输入观测、渲染观测、游戏报告接入与桌面路由；使用临时受管目录测试归档和保留策略。

### 必须通过的验收

1. 默认关闭归档时，已有命令及协议保持可用，不生成新的证据运行或持续落盘。
2. 显式 start/finish 归档同一服务中的多条命令；身份、commandId、步骤和截图引用一致，再次 start 不混合活动运行。
3. 两服务和两窗口运行隔离；共享 HTTP/Inspector 显示其实际共享运行。准确 runId 控制结束与导出。
4. 普通 CLI 开启归档后，一次输入或 game-autoplay 调用生成可读取的终态包；不依赖另一个短命进程的内存运行。退出后 export 仍可读取落盘记录。
5. 源码版本缺失、工作区有修改和运行版本未知如实记录，不将源码提交当作预览加载证明。
6. 日志采集范围、连接间隙、缓冲淘汰、文件缺失和截图失败都在包中可见；导出失败现场不触发新输入。
7. 收入包的截图在临时截图清理后仍可打开；包移动后内部引用仍能对应。
8. 容量、数量和实际输出字节不超限，截断有标记；清理只影响已结束且可验证归属的运行，活动运行和人工文件保留。
9. 不可写目录、写盘失败、碰撞和服务中止不会重复输入或伪造 complete；已有业务结果保持真实。
10. 真实鼠标与触摸点击分别命中目标时返回目标 UUID 和路径；输入与命中反馈可以对应实际业务变化。
11. 上层 BlockInputEvents/按钮遮挡时，反馈显示实际接收者，底层业务不变，verify 不把 sent 或 hit 当作购买成功。
12. 完整可观测的空白点击为 miss；观测故障、无法关联和截断为 unknown/partial；不兼容为 unsupported，键盘为 not-applicable。
13. 没有 UI 目标但全局输入仍推进玩法的场景不因 miss 被错误判定为业务失败。
14. 冒泡、鼠标合成触摸、拖动和长按不会制造虚假重复命中；坐标缩放、不同 DPR 和相关 canvas 信息与实际点击一致。
15. 开启/关闭观察前后，原本无触摸资格的节点、正常事件传播、业务调用次数和既有第三方边界行为一致。
16. 部分输入失败仍释放指针/按键并保留有限反馈；刷新、场景变化、桥更换和服务关闭后无迟到输入、旧观察或反馈串轮。
17. 场景已存在但尚未完成绘制时，严格 render-ready 不提前成功；真实绘制后才 rendered，严格截图属于同一文档和场景。
18. 已过去的启动首帧不会被伪造，帧信息明确来源；缓存渲染确认在刷新或同名新场景后失效。
19. 暂停且无匹配渲染证据时返回 paused-unverified，不 resume、tick、重载或接管；普通截图仍能保存当前画面并标注状态。
20. 无渲染、能力缺失、排队过期和页面关闭有界结束；等待与截图共用总预算，无返回后的后台截图。
21. CLI、stdio、HTTP 的 schema、错误、输出容量与文件路径可用，证据/渲染工具不暴露任意 eval。
22. 桌面 Inspector 的人工复现、AI 接入、保存包与断开都维持同一页面；首次接入和导出不重载，服务退出按既有所有权释放。
23. 使用真实 Cocos 3.8.8 Chrome 场景验证触摸、遮挡、空白和渲染，并在实际 Electron 场景验证鼠标、原生输入反馈及暂停现场。两种验收不得并行争抢系统输入焦点。
24. CountRice 独立测试上下文通过真实输入完成既有升级或阶段继续目标，导出的包能对照前后快照、输入、命中反馈、verify 和停止原因；状态预置仅用于明确的测试准备，不由新工具开放。

实现完成后运行受影响的单文件测试、类型检查和最终完整工具测试，并执行上述实际 Chrome、桌面与 CountRice 验收。未取得真实证据的能力标注限制，不把模拟派发成功作为实际引擎验收。
