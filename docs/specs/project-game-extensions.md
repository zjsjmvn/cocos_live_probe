# 项目级游戏扩展：结构化状态、真实输入与有界自动玩

状态：用户已授权发布及实现；测试采用公共 dispatch 行为、CLI/MCP 协议及 CountRice 真实预览验收。

跟踪事项：[GitHub Issue #2](https://github.com/zjsjmvn/cocos_live_probe/issues/2)。

## Problem Statement

Cocos Live Probe 已支持场景与节点查询、动画采样、截图、真实浏览器输入、条件等待和持续诊断。开发者希望在单个游戏中增加自动玩、流程验证和游戏状态观察，而不需要把米桶、金币、鸡槽等业务知识加入通用探针，也不必在每次对话中重新解释全部玩法。

目前没有项目级插件加载机制。宿主游戏只能组合通用命令或编写 CLI eval 脚本。单靠截图判断难以准确识别升级条件、引导进度、动画中的输入锁和玩法是否真正推进；直接调用运行时命令又无法验证浏览器输入、弹窗遮挡和表现层绑定。CLI 与 stdio MCP 拥有不同页面，通过 CLI 执行游戏脚本也不能扩展另一个 MCP 会话正在观察的游戏。

开发者需要一个放在宿主仓库、显式加载、复用当前探针会话的游戏扩展。自动玩应有目标、能说明每一步为什么执行、验证实际结果，并在目标达成、无进展、页面变化或预算用尽时停止。

## Solution

新增最小项目级游戏扩展能力。通用探针负责加载扩展、维持页面所有权、执行真实输入、管理时限和输出报告；游戏扩展负责结构化状态、目标解释、操作目标定位、策略决策及业务结果判断。

游戏在开发预览中提供只读观察桥，统一返回玩法快照和必要的界面状态。自动玩通过现有浏览器输入改变玩法；观察桥只提供数据。首个适配对象为 CountRice，其扩展留在宿主仓库，通用探针仓库不包含 CountRice 规则。

对外提供三个游戏入口：

| MCP 工具 | CLI 命令 | 用户可见行为 |
| --- | --- | --- |
| `game_state` | `game-state` | 读取插件、游戏与页面身份，以及当前玩法和界面状态 |
| `game_step` | `game-step` | 完成一次观察、决策、输入或等待、结果验证，并解释结果 |
| `game_autoplay` | `game-autoplay` | 在目标、时间、步数和无进展限制内重复单步，返回有界报告 |

第一版每个服务实例显式启用一个游戏扩展。未配置扩展时，既有 CLI 和 MCP 的工具列表、行为与生命周期保持兼容。用户可先单步观察策略，再运行短批次自动玩；更长的推进由调用者逐批发起并重新检查状态。

## User Stories

1. 作为游戏开发者，我希望把游戏专属扩展保存在宿主仓库，以便玩法变化和扩展代码一起维护。
2. 作为通用探针维护者，我希望核心只认识通用操作和扩展契约，以便同一工具能接入不同游戏。
3. 作为游戏开发者，我希望显式配置扩展入口，以便知道当前启用了哪份本地代码。
4. 作为游戏开发者，我希望相对入口按宿主 workspace 解析，以便从不同工作目录启动时加载同一扩展。
5. 作为游戏开发者，我希望缺失入口、加载失败或契约版本不兼容时收到明确错误，以便快速修正配置。
6. 作为既有用户，我希望不配置扩展时原有命令继续工作，以便无需迁移所有项目。
7. 作为插件作者，我希望使用小而明确的扩展接口，以便专注游戏状态和策略。
8. 作为 AI 调试助手，我希望知道插件身份、契约版本和支持目标，以便按实际能力调用工具。
9. 作为 AI 调试助手，我希望读取结构化游戏状态，以便准确判断阶段、资源和进度。
10. 作为 AI 调试助手，我希望状态同时包含弹窗、引导和输入锁，以便解释当前为什么可以或不能操作。
11. 作为 AI 调试助手，我希望状态标明采集时间和页面身份，以便区分当前观察与旧报告。
12. 作为游戏开发者，我希望开发观察桥只返回数据，以便保持游戏状态由原有运行时管理。
13. 作为游戏开发者，我希望观察桥在开发预览之外不启用，以便发布版本不承担调试接入。
14. 作为游戏开发者，我希望场景停用和销毁时解除观察桥，以便不会读取旧屏幕或旧运行时。
15. 作为 AI 调试助手，我希望观察桥尚未就绪或游戏不匹配时获得明确状态，以便避免对错误场景执行输入。
16. 作为 AI 调试助手，我希望通过单步工具看到策略选择及理由，以便审查自动玩的行为。
17. 作为 AI 调试助手，我希望单步返回执行前后的游戏状态，以便判断该动作实际产生的效果。
18. 作为 AI 调试助手，我希望已达成的目标直接返回成功，以便不会多执行一次点击。
19. 作为游戏开发者，我希望自动玩发送真实鼠标或触摸输入，以便验证浏览器到游戏的完整交互链路。
20. 作为游戏开发者，我希望插件按当前节点身份定位目标，以便窗口缩放或界面移动后仍可正确操作。
21. 作为游戏开发者，我希望弹窗遮挡仍参与正常命中测试，以便自动玩能暴露界面问题。
22. 作为 AI 调试助手，我希望输入前取得当前观察凭据，以便避免使用旧页面或旧几何关系。
23. 作为 AI 调试助手，我希望场景变化后重新定位目标，以便不会使用已销毁的节点。
24. 作为 AI 调试助手，我希望业务成功由后续状态验证，以便不把输入已发送当作升级成功。
25. 作为游戏开发者，我希望部分发送或结果不明的输入不会自动重放，以便避免重复购买和领取。
26. 作为 AI 调试助手，我希望动画锁定时执行有界等待，以便正常表现完成后再继续。
27. 作为 AI 调试助手，我希望未知弹窗或无法解释的状态使执行停止，以便及时检查现场。
28. 作为 AI 调试助手，我希望按明确目标运行自动玩，以便清楚知道该批次的完成条件。
29. 作为 AI 调试助手，我希望限制总运行时长，以便一次工具调用不会无限占用会话。
30. 作为 AI 调试助手，我希望限制最大步数，以便频繁等待或无效操作也能终止。
31. 作为 AI 调试助手，我希望限制连续无进展时长，以便发现输入失效和策略卡住。
32. 作为 AI 调试助手，我希望自动玩说明停止原因，以便区分目标达成、预算用尽和执行失败。
33. 作为 AI 调试助手，我希望短批次之间重新观察游戏，以便根据最新状态决定是否继续。
34. 作为并行开发者，我希望插件只操作当前 stdio 会话的页面，以便其他会话的游戏不受影响。
35. 作为 CLI 用户，我希望游戏命令遵守既有 manual-cli 页面语义，以便连续调用保持游戏进度。
36. 作为 HTTP MCP 用户，我希望明确所有客户端共享当前服务实例，以便理解自动玩的并发限制。
37. 作为游戏开发者，我希望自动玩和普通读取、刷新遵守同一队列，以便动作验证期间页面不会被本服务另一个命令修改。
38. 作为游戏开发者，我希望服务关闭后停止插件工作并释放本次输入，以便不会留下后台计时器或持续按压。
39. 作为 AI 调试助手，我希望失败报告包含已有诊断的游标和可用证据，以便继续检查异常。
40. 作为游戏开发者，我希望执行报告受到容量限制，以便高步数运行不会产生无限输出。
41. 作为 CountRice 开发者，我希望先处理已支持的引导和弹窗，以便自动玩遵守玩家实际可操作流程。
42. 作为 CountRice 开发者，我希望观察米桶、米袋、首轮吃米储备和米槽的独立状态，以便不把不同容器混算。
43. 作为 CountRice 开发者，我希望根据实际升级报价和可购买条件选择升级，以便扩展不复制经济公式。
44. 作为 CountRice 开发者，我希望米桶飞行、米槽切换和完成表现期间等待实际输入恢复，以便不绕过表现层。
45. 作为 CountRice 开发者，我希望通过正常完成按钮进入下一阶段，以便验证数米和吃米的交接流程。
46. 作为 CountRice 开发者，我希望达到指定升级等级或阶段后停止，以便复现明确的玩法状态。
47. 作为 CountRice 开发者，我希望策略选择稳定且能解释优先级，以便复查同一起始条件下的执行。
48. 作为 CountRice 开发者，我希望自动玩使用现有存档规则，以便记录真实玩法推进后的状态。
49. 作为插件作者，我希望通过公共游戏命令验证扩展行为，以便测试不依赖内部辅助函数布局。
50. 作为其他 Cocos 游戏的开发者，我希望参考数米接入说明实现自己的扩展，以便复用同一生命周期和输入能力。

## Implementation Decisions

### 1. 模块分工和首版范围

- 扩展现有命令模型、RuntimeProbeService、CLI 和 MCP 适配模块；新增最小扩展加载模块和游戏执行模块。继续复用 CDP、页面身份、截图凭据、输入清理、诊断缓冲区与服务队列。
- 项目插件作为宿主仓库中的本地模块管理，声明插件 ID、接口契约版本、预期游戏 ID、观察状态版本、支持目标及必要的 Cocos 能力。首版每个服务实例只加载一个显式配置的插件。
- 插件的行为接口收敛为读取状态、根据状态与目标决定下一步、验证前后状态三个职责。通用执行模块统一完成输入、等待、限额和报告；插件不另建浏览器连接或自行启动自动玩后台循环。
- 插件可以在本地内部组合状态翻译、界面定位和策略模块，但不强制每个游戏实现完整通用策略引擎。
- 首版交付包括通用扩展能力和 CountRice 接入。通用仓库负责接口与无游戏依赖的测试；宿主仓库负责观察桥、数米插件和真实玩法验收。两个仓库分别提交，并在宿主引用已验证的子模块提交。

### 2. 配置、加载和能力发现

- 服务选项提供显式扩展入口；CLI 和 MCP 启动支持环境配置。显式服务选项优先于环境配置，相对入口以服务的宿主 workspace 为基准，绝对入口直接使用。
- 配置的入口是开发者管理的本地可执行模块。不存在时不静默禁用或切换到其他插件；加载失败、声明缺失和不兼容的契约版本报告明确原因。
- 复用现有 TypeScript/Node 启动环境，支持其能够加载的本地模块，不下载插件、不自动安装依赖、不把目录扫描结果当作隐式授权。
- MCP 会话启动时确定扩展与工具 schema，运行中不热加载。配置变更需重启该服务实例；未配置扩展时保留原有工具列表，CLI 游戏命令返回未启用扩展的错误。
- 加载成功时增加三个标准游戏工具，状态入口报告插件与目标能力。CountRice 目标和字段由插件提供 schema 与说明，通用探针不硬编码数米名称。
- MCP 客户端仅提交已声明的结构化目标、策略参数和运行预算；不能提交 JavaScript、任意脚本路径或动态插件入口。现有 MCP 不暴露通用 eval 的契约继续成立。

### 3. 当前会话上下文与执行顺序

- 为插件提供绑定当前服务实例的操作上下文。上下文复用当前受管 target、BrowserContext、完整 URL、文档身份和刷新代次，并只允许声明的状态读取、节点查询、截图、真实输入、条件等待和诊断操作。
- 插件操作必须经过既有所有权校验。不得通过 CLI 子进程、按 origin 查找其他页面或另建服务实例完成当前 MCP 的操作。
- 状态、单步和自动玩都通过公共 dispatch 进入现有队列。一轮单步的观察、动作和验证不可被同服务的刷新或输入插入；有界自动玩批次占用同一队列，其他会话继续独立运行。
- 队列内部提供不会重新排队的受控操作上下文，复用现有底层执行路径。插件不得在正在执行的队列任务中递归等待公共 dispatch，避免自身等待自身的死锁。
- 执行开始前记录总截止时间，排队、准备、读取、截图、输入、等待和验证共享剩余预算；超时后不开始新动作，输入释放使用单独的短清理窗口。
- 操作上下文在调用结束、超时或服务释放时失效；异步插件即使迟到返回，也不能继续用旧上下文发送输入。底层操作传递剩余时限，不能仅对外返回超时而让原操作继续修改游戏。第一版要求受信任插件遵守异步时限，不承诺终止阻塞 Node 事件循环的任意插件代码。
- 一次自动玩批次绑定初始文档和游戏实例。页面丢失、人工刷新、顶层导航或游戏桥实例替换导致当前批次停止，不自动接管新页面。后续由用户或调用者显式恢复、重新观察并决定是否继续。
- 同文档的已支持场景切换可继续，但必须验证游戏身份、重新取得桥状态和节点；观察桥缺失或新场景不受支持时明确停止。
- CLI 保持 manual-cli 共享页面模式；stdio 保持每会话独占上下文；HTTP 保持每服务共享模式。文档明确 CLI 进程间不能把单次调用期间的诊断视为连续日志，也不承诺不同进程的多步批次互斥。

### 4. 游戏内只读观察桥

- 宿主表现层在开发预览中注册版本化、带游戏 ID 和实例标记的只读桥。桥在启用时绑定当前运行时，在停用或销毁时仅解除自己注册的实例；发布构建不启用该桥。
- 桥返回可序列化、与运行时分离的数据。玩法字段来自现有 facade 快照；暂态字段通过最小只读投影取得，不把 ECS 或 Cocos 对象句柄交给外部，也不复制第二套玩法规则。
- 一次读取同步采集玩法快照和相关界面状态，返回阶段、资源、目标进度、输入就绪及其阻塞原因、当前引导/弹窗和操作目标身份。独立界面事实仍可能在返回后变化，输入后必须验证实际结果。
- 通用核心只识别桥身份、版本、实例标记及可序列化载荷，具体游戏字段由插件解释。桥未就绪、游戏不匹配、版本不支持和数据格式不合法分别报告。
- 桥与扩展不提供改金币、注入米量、跳引导、结束动画、加速 tick 或修改存档的自动玩操作。生产状态仍由原有 ECS 运行时及正常玩家输入推进，遵守宿主运行时与表现层 ADR。
- 第一版通过固定的桥读取与节点查询获得数据，不向 MCP 暴露任意执行表达式。受信任的本地插件不是沙箱，其只读约束通过公开契约、代码审查与行为测试落实，不声称能隔离恶意插件代码。

### 5. 统一状态和目标契约

- `game_state` 返回插件 ID、契约/状态版本、游戏 ID、当前桥实例标记、实际采集时间、页面/文档身份、就绪状态与游戏载荷。可检测能力和不支持原因如实返回。
- 状态读取也受单步级时限约束，不运行游戏 tick、不发送输入、不触发存档。插件声明的 goal 和策略 schema 用于生成 MCP 工具参数，CLI 使用同一校验规则。
- `game_step` 和 `game_autoplay` 接受插件声明的结构化 goal 与策略参数，未知目标、未知字段、非法预算在任何输入之前拒绝。CountRice 首版支持指定升级项达到目标等级和达到指定玩法阶段。
- CountRice 指定升级目标采用现有升级类型；阶段目标采用 countRice/eatRice，目标已经达成时返回成功且不发送输入。不承诺跨版本私有字段兼容或在一个批次中完成一亿目标。
- 策略默认使用固定、可解释的优先级；不依赖模型在每一步临时生成 JavaScript。决策报告包括动作类别、目标、理由和业务完成条件。
- 目标或插件声明不匹配时不得猜测等价字段或降级为坐标乱点。

### 6. 单步执行与真实输入

- 单步严格执行观察、决策、动作/等待、再次观察和验证。动作可为已有点击、长按、拖动、按键，或无输入的有界等待；一轮最多一个主动操作，操作后不隐式追加购买或领取。
- 输入前重新定位当前目标并取得当前截图观察凭据，复用已有 UUID 投影、CSS 坐标、几何校验和正常命中测试。首次状态观察不保证动态对象位置被冻结。
- 识别已知动画与输入锁时等待明确条件，不强行修改锁、完成飞行或直接调用按钮回调。未知弹窗、歧义目标、不支持的节点或版本返回可区分的停止原因。
- 业务结果由插件比较前后状态和当前界面验证。报告分别保留浏览器输入发送/清理情况与业务判据结果；异步效果使用剩余预算进行有界等待，不能只靠固定延时断言成功。
- 部分输入失败或结果不明时停止，不自动重放该动作。后续显式调用先重新观察，只有最新状态能支持新决策时才执行。
- 单步返回前后状态、决策、动作、业务验证、耗时、页面身份和诊断范围。建议单步总时限默认 5 秒、上限 10 秒，动作时长和等待均不能超过剩余预算。

### 7. 有界自动玩和报告

- 自动玩重复同一单步行为，执行前和每轮后检查目标。达到目标立即结束；最后一个目标动作之外不再发送输入。
- 预算由总时长、最大步数和连续无进展时长组成，均使用单调时间。建议总时长默认 20 秒、上限 30 秒，最大步数默认 100、上限 1000，无进展时限默认 5 秒且不得超过总预算。输入释放的额外清理窗口最多 3 秒。
- 每次单步决策，包括仅等待的一轮，都计入步数。业务进展由插件根据目标与前后状态定义；时间戳、重复日志和无关字段变化不能重置无进展计时。正常被动收益只有在策略声明为目标相关进展时才计入。
- 停止原因至少区分目标达成、总时限、步数上限、无进展、当前状态受阻、业务结果不明、输入失败、页面/文档变化、桥不可用和插件错误。报告保留已经发生的输入，不声称能回滚玩法修改。
- 达到时间或步数限额是正常的批次结束，报告明确目标尚未完成；无进展和其他执行错误通过 MCP 工具错误返回结构化证据。运行前已完成的目标是正常成功。
- 报告包含初始/最终状态、目标完成情况、执行步数、耗时、停止原因及有界步骤记录。最多保留最近 50 条步骤记录、报告总量不超过 256 KiB，超出时显式标明截断并保留停止原因与关键摘要；无法容纳的原始游戏载荷明确标为被省略，不静默伪装完整快照。
- 失败时引用已有诊断游标及可用最后截图，不假定截图和日志一定取得成功，也不另建录屏或无限现场采集机制。
- 自动玩在该次调用结束时停止，无后台定时器、任务句柄或自动续跑。调用者发起下一批时重新读取当前状态；服务关闭释放插件监听和本次仍持有的输入，不影响其他会话。
- 默认预算适配宿主当前 45 秒 MCP 工具超时；部署说明明确工具超时须覆盖总预算和清理时间。第一版不承诺传输中断立即取消；即使客户端断开，执行也必须受既定总预算约束。

### 8. CountRice 插件与观察数据

- 插件和开发桥由 CountRice 宿主维护，使用现有 facade、状态快照和表现层读取。ECS 组件仍是玩法状态权威；不添加第二份数米/吃米实现或改写已有领域规则。
- 状态投影至少覆盖阶段、待切换阶段、完成表现、数米/吃米目标进度、引导进度、金币和相关升级状态，以及米桶、物理米袋、首轮吃米储备、当前米槽和鸡槽。遵守独立容器 ADR，不从剩余米倒推无法证明的历史累计。
- 输入就绪投影同时考虑运行时的活动输入阶段、米桶飞行和米槽切换，以及表现层的活动状态、已知弹窗、引导和相应目标的实际可操作条件。阻塞原因采用显式状态，不仅看持久化快照或节点存在。
- 升级候选从现有运行时/表现读模型取得等级、报价和是否可购买。若现有端口缺少数据，只增加最小只读查询并复用原有数值规则，不在插件内复制升级公式。
- 首版确定性优先级为处理已支持引导和可通过普通按钮完成的弹窗、等待已知暂态锁、确认目标、执行目标相关的合法升级/阶段继续操作、按当前阶段进行数米或吃米输入。引导或弹窗遮挡时不同时操作底层按钮。
- 至少支持初始数米引导、普通离线收益领取或关闭、首次数米完成后的正常继续操作，以及当前数米/吃米输入和一个升级项。对广告、付费或其他未支持流程返回阻塞原因，不默默领取额外奖励。
- 自动玩使用正常存档路径，不修改或替换玩家存档。真实验收使用独立测试上下文及明确的测试存档/起始状态；测试准备独立于玩家自动玩接口，不把预置状态能力开放给 MCP。

### 9. 文档、兼容与交付

- 增加扩展配置、插件契约、桥生命周期、目标 schema、三个 CLI/MCP 入口、报告与停止原因的使用说明，并给出数米接入示例。
- 扩展配置说明明确宿主根路径解析、stdio/CLI/HTTP 页面语义以及只读桥必须与游戏版本匹配。通用工具升级后宿主更新子模块引用，再进行实际接入验收。
- 保留原有 eval/eval-file、运行时诊断脚本与回归入口。它们仍可单独用于开发诊断，不是当前 MCP 插件执行的跨会话通道。
- 完成状态应以公共行为测试和真实输入验收为依据；配置加载成功、场景 ready 或单独输入 sent 都不足以证明自动玩完成。

## Testing Decisions

### 主要测试入口

以现有 `RuntimeProbeService.dispatch` 为主要行为测试入口，验证加载配置后对外可见的状态、单步、自动玩结果、时间上限、页面隔离和失败恢复。复用现有浏览器/CDP、时钟、文件和事件依赖，测试调用者能观察的结果，不按辅助函数数量、表达式字符串或固定 CDP 调用顺序断言实现。

通用测试使用不包含 CountRice 规则的测试插件与测试桥，借助现有 FakeRuntimeProbeEnvironment、FakeSocket 和交互测试夹具模拟界面状态及输入效果。插件本身通过这同一个入口验证，优先使用已有依赖注入，不在每个内部模块建立新的 mock 接口。

CLI、stdio MCP 和 HTTP MCP 仅增加公共协议测试，核对工具发现、参数 schema、错误、配置解析及输出容量。真实 Cocos 3.8 预览测试验证浏览器到引擎的输入链路；CountRice 宿主验收结构化观察、引导、升级、暂态锁和正常阶段交接。fake 的输入成功不能替代真实页面业务验证。

### 必须覆盖的行为

1. 未配置插件时原有工具列表和命令行为保持兼容；配置的本地模块被加载，相对路径从 workspace 解析，显式配置优先，缺失/非法入口和不兼容契约明确失败。
2. 开发桥身份与版本匹配时读取结构化数据；桥未就绪、游戏不匹配、实例失效或数据不合法时不执行输入；正常发布构建不注册桥。
3. 只读状态入口不改变玩法、存档或游戏速度；停用旧屏幕后不能读取旧实例，场景启用后取得新桥实例。
4. 目标已达成时单步和自动玩均不输入；非法目标和预算在任何输入前失败；有效单步返回可解释决策、前后状态及业务验证。
5. 真实 UI 点击和长按能推进测试游戏；遮挡时底层状态不变，系统不把 sent 当成功；UUID 目标刷新后重新定位。
6. 正常已知动画锁导致有界等待后继续；未知弹窗和歧义目标停止；等待也消耗步数，无法以等待绕过预算。
7. 输入部分失败和验证结果不明时不重放；超时/失败释放本次按键与指针，连接丢失时报告清理未确认。
8. 排队时间、准备、读取、截图、输入、等待及验证共同受总截止时间限制；预算已过的排队任务不开始新的输入；遵守契约的异步插件超时不会破坏后续队列，迟到完成也不能再使用旧上下文发送输入。
9. 自动玩在目标、时限、步数或无进展阈值到达时停止，状态原因区分完整；无关时间戳变化不重置进展计时。
10. 达到预算正常返回未完成摘要，业务失败通过 MCP 保留结构化错误；步骤和报告截断可见，关键停止信息始终保留。
11. 当前服务的刷新和输入不插入单步或批次中；插件上下文不会递归排队死锁；另一 stdio 会话的页面、诊断与队列不受影响。
12. 人工刷新、导航、target 丢失及桥实例替换使运行停止，旧凭据不得继续输入；显式恢复后重新观察才能执行下一批。
13. 返回后没有后台续跑；服务释放解除插件监听与上下文，不关闭共享浏览器或其他会话；CLI/HTTP 保持已声明的共享语义。
14. MCP 只接受结构化参数，不增加通用 eval 或远程插件加载；CLI、stdio 与 HTTP 的工具发现、映射、错误和输出保持一致。
15. CountRice 观察投影正确区分米桶、物理米袋、首轮吃米储备和当前米槽，并如实显示运行时与表现层的输入锁，不改写 ECS 权威状态。
16. CountRice 使用正常触摸输入完成初始数米引导，通过界面完成至少一次指定升级，并在目标等级到达时停止；不能靠调用 facade 命令代替验收。
17. 在明确的 CountRice 测试起始状态下，普通弹窗正常处理、米桶飞行期间等待，首次数米完成后通过完成按钮切换到吃米；广告或未知流程明确受阻。
18. CountRice 分批自动玩保留真实进度并重新观察；测试存档准备不成为自动玩接口，现有运行时、表现层和回归检查继续通过。

通用实现验收运行现有类型检查、公共命令/协议测试及真实浏览器验收。宿主实现验收运行现有运行时和表现层测试、迁移检查与上述 CountRice 真实预览流程。需要 Creator 预览或浏览器而环境不可用时，记录尚未完成的实际验收，不以 fake 结果代替。

## Out of Scope

- 插件市场、远程安装、目录自动扫描、插件热更新、多插件同时路由、对不受信任本地代码的沙箱隔离，以及强制终止阻塞事件循环的任意插件代码。
- 新的浏览器驱动、CLI/MCP 跨会话页面接管、HTTP 按客户端隔离，以及跨 CLI 进程的批次互斥。
- 通用 MCP eval、客户端提交脚本、自动下载或安装依赖。
- 无期限后台自动玩、start/status/stop 任务系统、自动续跑、定时运行或传输中断立即取消。
- 直接调用玩法命令替代真实输入、修改金币/米量/存档、强制跳引导/动画、加速或暂停游戏时间。
- 最优经济策略、机器学习训练、视觉模型自动生成操作策略，以及覆盖 CountRice 全部广告、奖励、生肖和自由模式流程。
- 保证一个短批次完成一亿米或一亿蛋目标，或仅凭节点存在/输入 sent 声称业务成功。
- 录制回放、视频、性能分析和新的无限诊断采集机制。
- 任意 3D 对象定位、多指手势、移动真机自动化及本轮声明以外的 Cocos 版本兼容。

## Further Notes

- 本规格整理自本轮关于单个游戏扩展的讨论：采用宿主项目插件、结构化只读观察、真实浏览器输入及当前会话执行；单步为核心，有界自动玩复用单步。
- 通用探针核对基线为提交 f18a3f3。已有截图、输入、条件等待和持续诊断作为前提，本规格增加游戏扩展层，不重复实现这些能力。
- 宿主遵守运行时与表现层分离、ECS 权威状态和独立米容器 ADR；最小只读投影不改变领域状态的所有权。
- 插件契约细节、桥字段、目标校验和预算默认值是为使实现可执行而提出的首版决定，不宣称此前已逐项确认。实现调整须同步 CLI/MCP schema、契约说明和行为测试。
- 用户已确认继续发布及实现；测试入口采用公共 dispatch 的行为测试、CLI/MCP 协议验证及 CountRice 真实预览验收。
- 发布到通用探针的 GitHub Issues，使用 ready-for-agent 标签；宿主插件与开发桥作为跨仓库交付的一部分记录和验收。规格发布不代表已实现。
